# Import recovery acceptance sandbox

This development-only workflow exercises overlapping transactions, a physical
statement containing two accounts, batch cancellation, and recovery from an
archive failure. It uses a disposable SQLite backup and fixture copies. It never
changes the saved ParseTrail database path or enables fault injection in a
distributed client.

The preparation tool requires an OCCU fixture already represented by exactly two
statement rows for two accounts in the source database. It removes those two rows
from the disposable copy so importing that fixture exercises the real
multi-account insertion path. Existing transactions remain in the copy.

From `client/`, prepare a run:

```powershell
uv run --frozen python ..\devtools\import_acceptance\prepare.py `
  --source-database C:\path\to\Tobias.db `
  --mohela-statement C:\path\to\new-life-of-loan.csv `
  --occu-statement C:\path\to\OCCU-fixture.pdf `
  --output-root C:\path\to\private-acceptance-runs
```

Use the printed database path for all three phases. Close the sandbox between
phases.

1. Launch with `--cancel-after 1`, choose **Import all statements**, and confirm
   that the MOHELA file imports while the OCCU file remains in the import folder.
2. Launch with `--fail-archive-for OCCU-fixture.pdf` and choose **Import all
   statements**. Confirm that the UI reports a recoverable archive failure and
   the OCCU source remains in the import folder.
3. Launch without an injection and acknowledge the pending-archive notice. Choose
   **Import all statements** again. The two OCCU statement rows must resolve to
   one canonical filename and the source must move to `SUCCESS` without adding
   duplicate statement or transaction rows.

Example launch:

```powershell
uv run --frozen python ..\devtools\import_acceptance\launch.py `
  --database C:\path\to\acceptance.db `
  --cancel-after 1
```

The launcher refuses the database saved in the real client configuration and any
database not accompanied by the marker generated by `prepare.py`. It also disables
automatic update checks and refuses to save preferences while the sandbox is
running.
