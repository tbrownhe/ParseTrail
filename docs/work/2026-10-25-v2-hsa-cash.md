## Scope and controlling decisions

Admit the finite HealthEquity cash-section family (`hsa_cash_line_pilot`) only
when bound to an asset with cash-component tracking. Preserve its printed posting
dates and full signed source amounts. Offer explicit expense/refund/income/income-
adjustment and owned movement review; never infer interest, contribution income,
medical spending or investment ownership from sign/description. A blank printed
description stays unknown in evidence. A code-owned generic accounting description
may identify the reviewed entry, with the unknown source text clearly disclosed;
do not invent a printed merchant or interest label.

Extend printed-source opening and statement/journal comparison under this exact
family/kind/scope rule. Preserve timing/origin review, zero/withdrawal, all source
and allocation guards, source capture/activity limitations and component-only
qualifiers. Do not drop the general account-total gate for arbitrary families or
claim the entire HSA/investment portfolio reconciled. Fidelity HSA/retirement period
summary rows remain nonposting: no gains/income/cash flows are created. Preserve
previously admitted evidenced account-total opening anchors, including those
families where the separate opening balance and reviewed timing/origin support
them. This packet adds the finite cash-component opening case, without revoking
old account-total opening behavior or promoting summary rows into activity.

Support the limiting partial-settlement case of one known source outflow and no
receipt evidence yet, after explicit review of an expected owned destination.
Keep that expectation as authored metadata, never a fabricated observation or a
positive financial posting to the destination. The only financial source effect
is the complete observed outflow; transfer clearing retains its unresolved amount.
This lets a reviewed cash-to-investment outflow remain unresolved without turning
it into an expense or inventing settlement. A later actual receipt is an atomic
whole-event replacement under the existing history/date/source-use rules. Fees
are explicit, never the residual. Pair suggestion/fully evidenced APIs retain
their current behavior; generic missing-receipt state is clearly distinct.

Preserve one profile/event history; evolve the pre-release schema and recreate
disposable profiles where semantic/format admission requires it. No arbitrary
manual journals, securities quantities/cost basis, loan principal/interest posting,
source parser changes, auto counterpart creation or historical reconstruction.
Only synthetic/disposable inputs. `category_service` initially owned the store,
settlement manifest and finite scope/description rules. The primary subsequently
became its sole writer and finished service validation; no concurrent store writers.
`positions_desktop` owns cash/settlement/transfer/opening/source-review GUI adapters
and focused interaction checks. The primary owns cash/report/export integration,
workspace wiring and shared contracts/record; `positions_integrity` independently
reviews financial/provenance/persistence claims. Agree the narrow API before
dependent edits and keep one writer per file. No recursive delegation.

## Result and review

The cash-section adapter already retains observed
`posting_date` rows and `cash_component` balances; its final small receipt has an
unknown description. The current settlement minimum of one receipt leaves the
common investment outflow pending. Reviewed expected ownership plus unresolved
clearing is a conservative extension of the existing partial-settlement policy;
no destination receipt or value is inferred.

Schema 20 and tagged `settlement-2` manifests retain the expected destination as
authored metadata. Its captured account name/kind/scope is service-owned; the GUI
submits the selected ID, reference and explicit ownership acknowledgement.
An expectation requires zero actual receipts, a distinct existing financial
account and a nonblank reference. Metadata cannot create a received amount,
destination posting or allocation. Whole replacement/withdrawal preserves original
dates and history; destination kind/scope remains protected by retained history.
Explicit fees alone reduce principal. Full source outflow is consumed once.

`v2_cash_source_policy.py` centralizes the exact HSA family/asset/component gate
and generic accounting label for unavailable source text. This applies across
ordinary review/correction/withdrawal/repair, transfer manifests, opening and
statement comparison. Rule 5 reconciliation retains explicit balance/tracking
scope. Older rules retain their historical payloads and become stale; current
malformed/mismatched scope is refused. Successful HSA checks say cash component;
capture, unclassified text and investment values remain separate qualifications.

The settlement editor supports the no-receipt choice, clears its expectation when
an actual receipt is selected, and displays retained history without inventing a
pair. Cash reports warn about unobserved expected receipts even for a destination-
only selection with zero actual rows/movement. Workbook event metadata exports
the expectation separately from actual source legs and exact journal money.
Source previews retain unknown descriptions; the generic reviewed-entry label
is explicitly separate. Opening/source-review/coverage dialogs qualify scope.

Independent review identified and resolved an HSA-family fallthrough that admitted
wrong kinds/scopes, a scope-history scan that bypassed bounded manifest validation,
and an unbound GUI row's optional scope handling. Regression checks cover each.
Final review found no remaining financial/provenance/persistence issue. A service
test's assumption that metadata authoring itself rejects every invalid family
combination was corrected: metadata may exist, but interpretation admission must
refuse it. This changed a test assertion, not accounting policy.
